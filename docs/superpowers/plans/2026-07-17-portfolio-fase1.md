# Gestione Portfolio — Fase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the ~126 existing portfolio images' metadata (title, category, order)
from a hardcoded manifest file into a Supabase table, and rewire the public
Portfolio page to read from the database instead of the static array — laying the
groundwork for a Fase 2 admin panel where Silvia can add/edit/hide images herself.

**Architecture:** Add a `portfolio_immagini` table (public-read via RLS) and
backfill it with one row per existing image, generated mechanically from the
current manifest data (verified to match `ContentService.buildGalleryItems()`'s
output exactly). Add `SupabaseService.getPublishedPortfolioItems()`, then switch
`Portfolio` from a synchronous `ContentService.galleryItems` property to an
async-fetched signal — same `afterNextRender` + signal pattern already used for
events. Category filter pills become dynamically derived from whatever categories
are actually present in the fetched data, instead of a fixed list. No physical
image files move — they stay published from `public/images/...` exactly as today.

**Tech Stack:** Angular 20 standalone components/signals, Supabase (Postgres),
Tailwind CSS v4.

**Spec:** `docs/superpowers/specs/2026-07-17-portfolio-fase1-design.md` — read it
first if anything below is ambiguous; the SQL and code shapes here are transcribed
directly from it.

## Global Constraints

- Exact new table: `portfolio_immagini` (`id` bigint identity PK, `src` text,
  `titolo` text, `categoria` text, `ordine` integer default 0, `pubblicato`
  boolean default true). Only a `select` RLS policy in this phase (`to anon,
  authenticated using (true)`) — no insert/update/delete policies (Fase 2's job).
- Exact TypeScript field names on `GalleryItem`: `id`, `src`, `title`, `category`,
  `ordine`. `category` is `string` (free text), not a fixed union type.
  `GalleryCategoryOption` is `{ value: string; label: string }`.
- `SupabaseService.getPublishedPortfolioItems()` filters `pubblicato = true` and
  orders by `categoria` ascending, then `ordine` ascending.
- Category filter pills are computed from the distinct `category` values actually
  present in the fetched items, prefixed with a `{ value: 'tutte', label: 'Tutte' }`
  entry — never a hardcoded category list.
- No new `*.spec.ts` test files: this codebase has zero unit tests for services,
  utils, or feature components (only the default Angular scaffold `app.spec.ts`
  exists) — follow that existing convention. Each task instead verifies via
  `npm run build` (must succeed with zero TypeScript errors) and, where noted, a
  manual check.
- Do not touch `getEventSeats()`, `getPublishedEvents()`, `prenotaPosto()`,
  `invalidateSeatsCache()`, `insertNewsletterSignup()` in `supabase.service.ts`, or
  any other page (Eventi, Home, Shop, gestione-prenotazioni) — this phase only
  adds new, additive database/service surface and rewires the Portfolio page.
- No physical image files move or get re-uploaded anywhere in this phase.
- The SQL migration (Task 1) must be run manually by the user in the Supabase SQL
  Editor — no subagent can do this. After Task 1's review is clean, pause and ask
  the user to run `supabase/portfolio_fase1.sql` before treating the feature as
  end-to-end verifiable (Tasks 2-5 still compile and can be built/reviewed without
  the DB being migrated yet).

- [ ] **Step 2: Add the method**

```ts
  /** Immagini portfolio pubblicate, ordinate per categoria poi per ordine manuale. */
  async getPublishedPortfolioItems(): Promise<GalleryItem[]> {
    const client = await this.getClient();
    const { data, error } = await client
      .from('portfolio_immagini')
      .select('*')
      .eq('pubblicato', true)
      .order('categoria', { ascending: true })
      .order('ordine', { ascending: true });
    if (error || !data) return [];
    return data.map((row) => ({
      id: row['id'],
      src: row['src'],
      title: row['titolo'],
      category: row['categoria'],
      ordine: row['ordine'],
    }));
  }
```
